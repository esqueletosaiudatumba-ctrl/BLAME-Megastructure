# Known Issues and Technical Debt

1. **No one canonical generator currently reproduces the active instance.** The active instance contains roughly 14,664 `stream/` functions and dispatchers. The separate `reference_kit/source/build_cubic_pack.py` emits an earlier ~123-function fixed-sector design. Reconcile these into one canonical deterministic generator.
2. **Forge-version compatibility still needs runtime confirmation.** The active instance metadata is now aligned to Forge `14.23.5.2860`, the documented target. Confirm the full stack launches with the selected CubicChunks and World Primer builds.
3. **Bootstrap network dependency.** `bootstrap.ps1` fetches World Primer and CubicChunks at first launch and makes optional OptiFine/BSL attempts. Verify URLs, compatibility, checksums if practical, logging and graceful failure. Optional graphics must not prevent the game from starting.
4. **No in-game test yet.** ZIP integrity was checked, but a full Minecraft launch/playthrough was not performed here. Validate on a fresh instance and do not overstate.
5. **World save assumptions.** The current save has `level.dat` and data/functions rather than conventional prebuilt region files; CubicChunks/world-initialization behavior must be checked. Avoid handing off a broken or blank world and calling it prebuilt.
6. **Automatic streaming reliability.** A file-level audit now confirms all 14,664 stream cells are referenced once, all sentinel coordinates match their detector, and sentinel coordinates are unique. Runtime trigger cadence and loaded-column behavior remain untested. Trace `World Primer -> setup -> timed dispatch -> xyz region detector -> stream function -> marker` and check whether dispatches cover the configured coordinates, including negative Y. Make cell generation idempotent and ensure the marker can't falsely mark an incomplete cell as done.
7. **Visual criticism to solve.** Earlier attempt was described by the user as small, pathetic, ugly, and not procedural. Redesign the actual composition; increasing command count alone is not success.
8. **Target user workflow.** The user wants an instance ZIP to import in ElyPrism, not a CurseForge modpack, not a standalone world ZIP requiring copying, and not instructions requiring running functions manually.
9. **Shader compatibility.** This is 1.12.2 + CubicChunks. Do not assume modern Iris/Sodium setup fits. Verify a compatible legacy shader loader, or keep shaders optional and prioritize an unmodded-with-shaders launch success only after CubicChunks alone works.
10. **Environment and format.** Functions use legacy 1.12.2 command syntax, block IDs and metadata. Check function command compatibility, `/fill` volume limits, loaded cubic area, and performance.
